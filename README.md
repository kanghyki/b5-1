# Mini Redis

Python 3.8 이상으로 구현하는 CLI 기반 인메모리 저장소입니다.
`subject.html`의 필수 기능과 Pub/Sub 보너스를 구현합니다.

## 구현 단계

커밋은 다음 순서로 구성합니다. 각 구현 단계에는 해당 기능의 검증을 포함합니다.

1. 프로젝트 범위와 구조를 문서화합니다.
2. 이중 연결 리스트, 체이닝 해시맵, 최소 힙을 직접 구현합니다.
3. 기본 저장소, UTF-8 메모리 계산, LRU 제거, 힙 기반 TTL을 구현합니다.
4. 명령 파서와 Redis 스타일 출력, 채널 기반 Pub/Sub을 구현합니다.
5. Unix domain socket과 단일 이벤트 루프로 데몬을 구현합니다.
6. 자동 시작, REPL·명령행 클라이언트를 연결하고 통합 검증합니다.

## 설계

- 데몬 하나가 데이터와 구독 상태를 소유하며 클라이언트들은 로컬 IPC로 연결합니다.
- Unix domain socket을 사용하므로 IP 주소나 TCP 포트를 열지 않습니다.
- 데몬은 단일 이벤트 루프를 사용하며 요청과 TTL 만료를 처리합니다.
- REPL은 연결을 유지하며 입력과 구독 이벤트를 처리합니다.
- 명령행 클라이언트는 명령 하나의 결과를 출력하고 종료합니다.
- 프로세스 종료 시 데이터는 사라집니다. 파일 저장은 하지 않습니다.
- `dict`, `set`, `collections`로 핵심 자료구조를 대체하지 않습니다.
  Python 리스트는 버킷·힙 등의 인덱스 기반 배열 저장소로만 사용합니다.
- 구독자는 연결 단위이며 메시지를 구독자별 연결 리스트 큐에 저장합니다.
- 느린 구독자의 버퍼는 제한하며 연결이 종료되면 구독을 해제합니다.

자료구조는 `mini_redis/structures/`, 저장소·명령·Pub/Sub·IPC는
`mini_redis/`의 독립 모듈로 분리합니다. 실행 진입점은 `main.py`입니다.

## 요구사항 해석

- 키를 사용하는 명령과 전체 조회 전에 만료된 키를 제거합니다.
- LRU는 성공한 `SET`, `GET`에서만 갱신합니다.
- 메모리 사용량은 키와 값의 UTF-8 바이트 수 합계입니다.
- 단일 엔트리가 제한보다 크면 기존 데이터 변경 없이 OOM을 반환합니다.
- `CONFIG SET maxmemory`로 제한을 낮추면 다음 성공한 `SET`에서 제거합니다.
- Pub/Sub 채널과 버퍼는 키 저장소와 별도이며 `used_memory`에 포함하지 않습니다.
- 구독 전 메시지는 보관하지 않으며 중복 구독은 중복 전달하지 않습니다.
- 명령 이름은 대소문자를 구분하지 않고 키·채널·값은 구분합니다.
- 자동 시작을 위한 프로세스 잠금은 데몬 중복 실행만 방지합니다.
  저장소에는 스레드나 데이터 접근 잠금을 사용하지 않습니다.

## 검증

표준 라이브러리 `unittest`를 사용합니다.

```sh
python3 -m unittest discover -s tests -v
```
